# Secure Phase Verification Protocol (SPVP) v2.5

**Status:** Implemented  
**Version:** 2.5  
**Encryption:** SPEKE (Simple Password Exponential Key Exchange)  
**Curve:** Diffie-Hellman (Mod P)

## Overview

SPVP provides a cryptographically secure method to verify if two players are in the same Epsilon phase without relying on trust-on-first-use (TOFU) or easily spoofed map coordinates. It uses a **Zero-Knowledge Proof** approach where players prove they know a shared secret (the "Phase Salt") without transmitting it over the wire.

## Core Concepts

### 1. Phase Salt
A 64-character hex string generated by the phase owner/officer.
- **Storage:** Stored in Epsilon Phase Addon Data (`TRP3FW_SPVP_KEY`).
- **Access:** Only readable by players actually inside the phase (server-enforced).
- **Format:** `HEX_STRING:TIMESTAMP` (e.g., `A3F2...:1704844800`)
- **Rotation:** Recommended every 30 days.

### 2. The Generator
The Diffie-Hellman generator `G` is derived from the Phase Salt.
- `G = (Hash(PhaseID + PhaseSalt)^2) mod P`
- This ensures that if two players have different Salts (i.e., different phases), they calculate different Generators, and the handshake fails mathematically.

### 3. Session IDs
Unique 8-character hex strings generated for each handshake to prevent replay attacks.
- **Anti-Replay:** Bob caches seen Session IDs for 60 seconds.

## Protocol Flow

### Stage 1: Initialization (Alice -> Bob)
Alice (Verifier/Prover) wants to check if Bob is in the same phase.

1.  **Alice** generates:
    - `a` (Private Key): Random [2, P-2]
    - `A` (Public Key): `G^a mod P`
    - `SessionID`: Random 8-char hex
2.  **Alice** sends `INIT`:
    ```
    INIT:2:SessionID:A
    ```
    *(Version:SessionID:PublicKey)*

### Stage 2: Response (Bob -> Alice)
Bob receives `INIT`.

1.  **Bob** checks `SessionID` cache (Replay Protection).
2.  **Bob** derives `G` using his local Phase Salt.
    - If Salt is missing/loading: Queue message.
    - If Phase is unsecured (No Salt): Send `NOSALT`.
3.  **Bob** generates:
    - `b` (Private Key): Random [2, P-2]
    - `B` (Public Key): `G^b mod P`
4.  **Bob** calculates Shared Secret `K`:
    - `K = A^b mod P`
5.  **Bob** creates Verifier `V`:
    - `V = Hash(K)`
6.  **Bob** sends `REPLY`:
    ```
    REPLY:SessionID:B:V
    ```
    *(SessionID:PublicKey:Verifier)*

### Stage 3: Verification (Alice)
Alice receives `REPLY`.

1.  **Alice** calculates Shared Secret `K`:
    - `K = B^a mod P`
2.  **Alice** calculates expected Verifier `V'`:
    - `V' = Hash(K)`
3.  **Alice** compares `V` vs `V'`.
    - **Match:** Bob is in the same phase.
      - Alice caches Bob as `SPVP_VERIFIED`.
      - Alice sends `CONFIRM` to Bob (3-way handshake).
    - **Mismatch:** Bob is in a different phase (or spoofing).
      - Alice blocks Bob.
      - Alice invalidates her local Salt cache (force refresh).

### Stage 4: Confirmation (Bob)
Bob receives `CONFIRM` (Optional but recommended).

1.  **Alice** sends `CONFIRM`:
    ```
    CONFIRM:SessionID:V'
    ```
2.  **Bob** verifies `V'`.
    - **Match:** Mutual verification complete.
      - Bob caches Alice as `SPVP_VERIFIED`.

## Packet Structure

Messages are sent via `C_ChatInfo.SendAddonMessage` on prefix `TRP3FW_SPVP`.

| Packet | Format | Description |
| :--- | :--- | :--- |
| **INIT** | `INIT:v:sid:pub` | Start handshake (Alice) |
| **REPLY** | `REPLY:sid:pub:ver` | Prove knowledge (Bob) |
| **CONFIRM** | `CONFIRM:sid:ver` | Confirm mutual trust (Alice) |
| **NOSALT** | `NOSALT:sid` | Phase is unsecured (Bob) |

## Implementation Details

- **Prime (P):** `90000049` (26-bit safe prime for Lua 5.1 doubles)
- **Hash:** FNV-1a (32-bit)
- **Timeout:** 5 seconds
- **Retries:** 2 attempts
- **Cache:** 5 minutes (SPVP Verified status)

## Security Considerations

1.  **Man-in-the-Middle (MitM):** Impossible without the Phase Salt. An attacker cannot derive `K` without knowing `G`, and they cannot know `G` without the Salt.
2.  **Replay Attacks:** Prevented by random Session IDs and strict 60s cache on Bob's side.
3.  **Spoofing:** An attacker in a different phase has a different Salt (or none). Their derived `G` will differ, resulting in a garbage `K` and mismatching `V`.
4.  **Performance:** Uses fast modular exponentiation (binary method) to ensure negligible frame drops.
